# ICONIC Real Estate — دليل التركيب والتشغيل

موقع الشركة (عربي + إنجليزي) بداشبورد إدارة كاملة وصندوق طلبات العملاء وإعدادات SEO، على سيرفر واحد بدون أي خدمات خارجية مدفوعة.

الموقع بيشتغل على Node.js بدون مكتبات خارجية، وقاعدة البيانات ملف SQLite واحد. يعني النسخ الاحتياطي سهل، والتشغيل يكفيه VPS صغير (1 CPU / 1 GB RAM).

---

## اللي محتاجه

- سيرفر VPS بنظام Ubuntu 22.04 أو أحدث (أي مزوّد: Hetzner, DigitalOcean, Contabo, …).
- الدومين بتاعك، وتقدر تعدّل الـ DNS بتاعه.
- بورتات 80 و443 مفتوحة على السيرفر.

## التركيب خطوة بخطوة (Docker + HTTPS تلقائي)

> ملف `.env` فيه الباسورد، فخلّي الـ zip عندك بس ومتبعتوش لحد.

**1) الـ DNS.** من لوحة الدومين اعمل سجلين من نوع `A` بنفس الـ IP بتاع السيرفر:

| Name | Type | Value |
|------|------|-------|
| `@`  | A    | IP السيرفر |
| `www`| A    | IP السيرفر |

استنى لما يبقوا شغالين (دقايق لساعات). تقدر تتأكد بـ `ping your-domain.com`.

**2) ثبّت Docker على السيرفر:**

```bash
curl -fsSL https://get.docker.com | sh
```

**3) ارفع الملفات.** فك الـ zip في `/opt/iconic` على السيرفر (مثلاً بـ `scp` ثم `unzip`).

**4) ملف الإعدادات.** النسخة اللي في الـ zip فيها ملف `.env` متجهّز بالدومين وحساب الأدمن وكود جوجل (ملف مخفي، اسمه بيبدأ بنقطة). راجعه بـ `nano .env`. لو بتبدأ من الصفر: `cp .env.example .env` وعدّل:

- `SITE_DOMAIN` — العنوان الأساسي للموقع من غير `https://` (زي ما جوجل هيفهرسه، مثلاً `www.example.com`).
- `ALT_DOMAIN` — الشكل التاني من نفس الدومين (من غير `www` مثلاً)، وبيتحوّل تلقائي للعنوان الأساسي.
- `ADMIN_EMAIL` و`ADMIN_PASSWORD` — حساب الأدمن الأول (الباسورد 10 حروف على الأقل، والأفضل أطول).

**5) شغّل:**

```bash
docker compose up -d --build
```

أول مرة هياخد كام دقيقة. Caddy هيجيب شهادة HTTPS لوحده ويجددها كل فترة.

**6) افتح** `https://your-domain.com` وللداشبورد `https://your-domain.com/admin`.

بعد أول دخول:

1. من داشبورد ← **الحساب** غيّر الباسورد.
2. امسح السطر `ADMIN_PASSWORD` من ملف `.env`. هو بيتقري مرة واحدة بس لما مفيش أي مستخدم في القاعدة، فمسحه آمن.
3. اقفل كل البورتات ما عدا SSH و80 و443: `ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw enable`.

لو نسيت الباسورد: `docker compose exec app node server/cli.js set-password you@example.com` (لازم تكون مسحت `ADMIN_PASSWORD` من `.env`، وإلا الأمر هيستخدم القيمة اللي فيه بدل ما يسألك).

> لازم يبقى عندك سجل DNS للشكلين (`@` و`www`) عشان Caddy يطلّع شهادة لكل واحد. لو مش عايز تحويل من الشكل التاني، امسح البلوك التاني من `Caddyfile` وسطر `ALT_DOMAIN` من `docker-compose.yml`.

### سيرفر عليه Nginx وأنظمة موجودة

شغّل التطبيق فقط، على عنوان محلي لا يفتح بورت عام جديد:

```bash
docker compose -f docker-compose.yml -f docker-compose.nginx.yml up -d --build app
chmod 755 backup.sh
```

ملفا `deploy/nginx-iconic-*.conf` يضيفان مسارات الموقع داخل إعداد HTTPS للدومين، مع الإبقاء على مسارات الأنظمة القديمة. انسخ ملف البروكسي إلى `/etc/nginx/snippets/iconic-website-proxy.conf` وملف المسارات إلى `/etc/nginx/snippets/iconic-website-locations.conf`، ثم أضف `include /etc/nginx/snippets/iconic-website-locations.conf;` داخل بلوك HTTPS الخاص بالدومين فقط. احتفظ بالشهادة الحالية، وافحص `nginx -t` قبل عمل reload. لا تشغّل Caddy في هذا الوضع.

الموقع يستخدم `/iconic-api/` و`/iconic-assets/` لتجنّب التداخل مع `/api/` و`/assets/` الخاصة بالأنظمة القديمة. ملف الترجمة الثابت هو `server/i18n.json`؛ ليس جزءًا من بيانات المستخدمين في `data/`.

### بدون Docker

محتاج Node.js **22.13 أو أحدث**:

```bash
SITE_URL=https://your-domain.com TRUST_PROXY=1 ADMIN_EMAIL=you@example.com npm start
```

وحط قدامه Caddy أو Nginx يعمل HTTPS ويبعت على `127.0.0.1:3000`. `TRUST_PROXY=1` لازم يتحط لما في Proxy قدام السيرفر، عشان حدود المحاولات تتحسب على IP الزائر الحقيقي مش على الـ Proxy.

## الداشبورد

كل النصوص والصور والفرق والمندوبين والوحدات بتتعدّل من `/admin`:

- **الطلبات**: كل استفسار بيوصل من الموقع بيتسجل هنا بحالته (جديد، تم التواصل، معاينة، مقفول، سبام) وتقدر تنزّله CSV.
- **الوحدات**: لكل وحدة صفحة خاصة بيها على الموقع، وليها حقلين SEO اختياريين (عنوان ووصف).
- **SEO**: عنوان ووصف الصفحة الرئيسية وصفحات المناطق، مع قايمة فحص ومعاينة شكلها في جوجل.
- **الفروع**: عناوين فروع الشركة (اسم، عنوان، تليفون، واتساب، ساعات العمل، لينك الخريطة)، بتظهر في قسم التواصل وفي فوتر الصفحات الداخلية.
- **الوظايف**: بتفتح وتقفل وظيفة من الداشبورد، وكل وظيفة مفتوحة ليها صفحة على `/ar/careers` و`/en/careers` وبتظهر في جوجل كوظيفة.
- **طلبات التوظيف**: كل متقدّم بيوصل هنا مع الـ CV (PDF أو Word، لحد 5 ميجا)، وتقدر تغيّر الحالة (جديد، تحت المراجعة، مقابلة، تم التعيين، مرفوض) وتكتب ملاحظة وتنزّل CSV. ملفات الـ CV ليها صلاحية خاصة (للأدمن ومسؤول الموارد البشرية بس).
- **المستخدمين** (للأدمن بس): تضيف أي عدد من المستخدمين بدور من التلاتة: **أدمن** (كل حاجة)، **محرّر** (محتوى الموقع والطلبات)، **موارد بشرية** (الوظايف وطلبات التوظيف بس). الأدمن بيقدر يغيّر الدور أو كلمة السر (والمستخدم بيتسجّل خروج من كل الأجهزة)، ومينفعش تمسح نفسك ولا آخر أدمن.
- **نسخة احتياطية**: تنزيل كل المحتوى كملف JSON.

الداشبورد بيتفتح من العنوان `/admin` بس، ومفيش أي لينك ليه في الموقع العام. ملفات الـ CV بتتحفظ في `data/cv` وبتدخل تلقائيًا في `backup.sh`.

الطلبات **مابتتبعتش بالإيميل** (مفيش SMTP). بتلاقيها في الداشبورد، أو تحط `LEAD_WEBHOOK_URL` في `.env` فكل طلب جديد يتبعت كمان لـ Zapier / Make / n8n / Slack incoming webhook.

## الـ SEO

اللي الموقع بيعمله لوحده:

- صفحات HTML كاملة من السيرفر (جوجل بيشوف المحتوى من غير JavaScript)، لكل لغة رابط مستقل: `/ar/` و`/en/`، مع `hreflang`.
- صفحة لكل وحدة ولكل منطقة بعنوان ووصف وروابط ثابتة (لو غيّرت اسم الوحدة الرابط مابيتغيرش، ولو اتغير رابط قديم بيعمل تحويل 301).
- Structured data (JSON-LD) للشركة والوحدات ومسار التنقل، وOpen Graph وTwitter لمعاينة المشاركة.
- `sitemap.xml` فيه الصفحات الحقيقية بس، و`robots.txt`، وضغط، وكاش، وصور بـ lazy loading.
- المناطق اللي مفيهاش وحدات بتتعلّم `noindex` لحد ما تضيف فيها وحدات.
- الـ `robots.txt` بيمنع الفهرسة لحد ما `SITE_URL` يبقى `https` (يعني مفيش فهرسة غلط من نسخة تجريبية).

اللي لازم تعمله إنت (ده اللي بيفرق فعلاً في الترتيب):

1. **Google Search Console**: أضف الدومين. لو جوجل أداك كود بصيغة `google-site-verification=…` فده بتاع **سجل DNS**: ضيفه كسجل `TXT` على `@` من لوحة الدومين (وده بيوثّق الدومين كله). ولو اخترت طريقة **HTML tag** حط القيمة اللي في `content` بس في `.env` كـ `GOOGLE_SITE_VERIFICATION=` ثم `docker compose up -d`. بعد التحقق ابعت `https://your-domain.com/sitemap.xml`. نفس الكلام لـ Bing بـ `BING_SITE_VERIFICATION=`.
2. **Google Business Profile** للشركة (مهم جداً للوسطاء العقاريين في البحث المحلي)، وخلّي الاسم والتليفون والعنوان زي الموقع بالظبط.
3. املا لكل وحدة: وصف حقيقي، صور حقيقية، وعنوان ووصف SEO مخصوص. صفحة وحدة فيها كلام وصور حقيقية بتنفع أكتر من أي إعداد تقني.
4. اكتب مقدمة لكل منطقة من تبويب SEO (اسكندرية، الساحل، القاهرة، البحر الأحمر) بكلام عن المنطقة نفسها.
5. الترتيب في جوجل بياخد وقت وبيعتمد على المحتوى والروابط اللي بتشاور على موقعك، مفيش إعداد بيضمنه.

## النسخ الاحتياطي

الداتا كلها في فولدر واحد (`iconic_data` volume): قاعدة البيانات `iconic.db` والصور في `uploads/` وملفات الـ CV في `cv/`.

نسخة يدوية:

```bash
./backup.sh
```

بتعمل ملف `backups/iconic-التاريخ.tgz` فيه القاعدة والصور وملفات الـ CV، وبتمسح اللي أقدم من 30 يوم. للتشغيل كل ليلة:

```bash
crontab -e
30 3 * * * cd /opt/iconic && ./backup.sh
```

**انسخ فولدر `backups` على مكان تاني خارج السيرفر** (جهازك أو تخزين سحابي)، لأن نسخة على نفس السيرفر مش حماية لو السيرفر اتمسح.

الاسترجاع:

```bash
docker compose down
docker run --rm -v iconic_data:/data -v "$(pwd)/backups":/in alpine sh -c \
  "cd /data && tar xzf /in/iconic-2026-01-01.tgz && cp backups/iconic.db iconic.db && rm -f iconic.db-wal iconic.db-shm && chown -R 1000:1000 /data"
docker compose up -d
```

(غيّر التاريخ لاسم الملف عندك.)

## تحديث الموقع

- **تعديل المحتوى**: من الداشبورد، من غير أي إعادة تشغيل.
- **تعديل التصميم أو النصوص الافتراضية**: الكود المصدري في فولدر `frontend/`.

  ```bash
  cd frontend
  npm install
  npm run build          # بيعيد بناء public/assets وقوالب السيرفر (محتاج Node و Python 3)
  cd .. && docker compose up -d --build
  ```

  (`npm run icons` بيعيد رسم الأيقونات وصورة المشاركة لو غيّرت اللوجو.)
- **تحديث الكود**: استبدل فولدري `server` و`public` وشغّل `docker compose up -d --build`. الداتا في الـ volume ومش هتتأثر.

### مكتبات الأنيميشن (اختياري)

الأنيميشن (GSAP وThree.js) بيتحمّل من cdnjs. لو عايز يتخدم من سيرفرك، حط الملفات دي في `public/vendor/` وهي بتتستخدم تلقائياً: `gsap.min.js` (3.12.5) و`ScrollTrigger.min.js` (3.12.5) و`three.min.js` (r128)، وبعدها `docker compose up -d --build`.

## ملاحظات مهمة وحدود معروفة

- التخزين بـ `node:sqlite` وهو لسه وصفه "تجريبي" في Node (شغال ومستقر في الاستخدام، بس الـ API ممكن يتغير في إصدارات مستقبلية). الـ Dockerfile مثبّت على Node 22.
- مفيش إرسال إيميل، الطلبات في الداشبورد أو الـ webhook.
- الصور القديمة المرفوعة مابتتمسحش من على القرص لما تتبدل (بتاخد مساحة بس، ومفيش خطر).
- قايمة الوحدات من غير ترقيم صفحات، مناسبة لحد بضع مئات وحدة.
- الأمان: كلمات السر مشفّرة (scrypt)، الجلسات HttpOnly، حماية CSRF، حدود محاولات دخول ورسائل، رفع الصور بيتحقق من نوع الملف الحقيقي. حافظ على تحديث السيرفر وغيّر باسورد الأدمن.
